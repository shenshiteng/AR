# 永久性单一二维码方案

> 目标：**一张码，印上去就不再撕、不再换**，同时微信扫一扫和系统相机都能打开导航网站。
> 前提约束：不做双码组合，不嵌中心图案，不做位置参数区分。
> 配套工具：`tools/make_permanent_qr.py`（生成）、`tools/check_qr.py`（验证）

---

## 一页结论

| 问题 | 结论 |
|---|---|
| 码里放什么 | **只放一个你自己控制的、永不变的短地址**，不放任何环境参数 |
| 用不用短链 | 用，但必须是**你自己的域名**，不要用第三方短链服务 |
| 关键机制 | **三层结构**：码 → 稳定入口地址 → 302 跳转 → 当前实际应用。以后换托管、换域名、换框架，只改跳转，码不动 |
| 纠错等级 | **H（30%）**。永久码不会重印，容错优先于体积 |
| 码面尺寸 | 模块 ≥1mm（推荐 1.5mm 以上）；扫描距离(cm) ≈ 码面(cm) × 8~12 |
| 最大风险 | 域名到期 / 未备案 / 被微信拦截 —— 这三件事任一发生，码就废了 |

**一句话**：永久性不是"印得结实"，是**码里的东西永远不失效**。所以码只能当"门牌号"，不能当"房间里的家具清单"。

---

## 二、为什么这个码必须"什么都不带"

永久张贴意味着**这张码的内容一旦印上去就再也改不了**。凡是"将来可能变"的东西，一个字都不能进码：

| 不能进码 | 为什么 |
|---|---|
| `sharecode=COAQ2BOKWL` | 托管平台重新发布就会变 → 全部重印（我们刚踩过） |
| `?loc=P-B2-03` | 每个点位不同 → 变成多张码，违反单一码前提 |
| IP 地址 / 端口号 | 换服务器就废 |
| `/fp-ar.html` 这类具体文件名 | 页面改名就废 |
| 时间戳、版本号、设备号 | 一次性内容 |
| 第三方短链（bit.ly 等） | 服务商可能倒闭、域名容易被微信拦、可能被加广告 |

**能进码的只有两样**：协议（https）、域名 + 一条固定路径。

## 三、网址形式怎么定

### 3.1 三层结构（这是永久性的核心）

```
印刷的二维码
    ↓ 内容是 https://go.xxx.edu.cn/b2   ← 这一层永不改变
稳定入口（你控制的域名，做 302 跳转）
    ↓ 这一层随时可以改，不影响已印的码
当前实际应用（托管平台 / 学校服务器 / 以后换的任何东西）
```

**为什么必须加这一层**：如果不加，码里就得直接写死托管地址。一旦平台换、目录改名、分享码变化，全楼重印。加了这一层，改一行跳转配置就行。

实现方式任选其一，都很轻：
- Nginx / Apache 一条 302 规则
- 域名根目录放一个 `index.html` 做 `location.replace()`（JS 跳转，微信内同样有效）
- 云函数 / 边缘函数
- 请学校信息中心配一条跳转（最稳，但要走流程）

### 3.2 四条路径对比

| 路径 | 示例 | 永久性 | 建议 |
|---|---|---|---|
| **A. 官方域名子路径** | `https://lab.xxx.edu.cn/b2` | 最稳（学校域名长期持有） | **首选** |
| **B. 自有短域名 + 跳转** | `https://go.xxx.cn/b2` | 稳（需自己续费） | 次选，最灵活 |
| C. 第三方短链 | `https://bit.ly/xxxx` | 差（服务商风险） | 不推荐 |
| D. 直接用托管地址 | `https://xxx.app.workbuddy.host/?sharecode=...` | ❌ 不满足 | **只能做试点** |

**如果现在还没有自己的域名**，那就先别印永久码。用路径 D 出的码只能当临时测试用，贴上去迟早要撕——这正是要避免的事。

### 3.3 域名选择的四条硬规矩

1. **全小写、纯字母数字**，不要连字符、下划线、中文
2. **避开易混字符**：`0/O`、`1/l/I`、`5/S`、`2/Z`（手输或口头传达时容易错）
3. **越短越好**——每多一个字符，二维码就可能升一个版本、模块变小
4. **必须有续费责任人**。域名过期是全套方案唯一无法挽回的失败

### 3.4 参数规则

| 可以带 | 不可以带 |
|---|---|
| `?src=qr-wall` 这类**永不改变**的埋点参数 | `sharecode`、`loc`、`t=`、`v=` 等会变或按点位变的参数 |
| 固定路径 `/b2`、`/nav` | 具体文件名 `.html`（将来可能改名） |

如果业务上确实需要"扫了就知道在哪个位置"——那就必须每个点位一张码，**这就不是单一码方案了**。这条取舍见第九节。

### 3.5 网址长度 → 二维码版本 → 模块宽度

纠错等级 H 下（含 4 模块静区，所以总模块 = 4×版本+17+8）：

| 网址示例 | 字符 | 版本 | 总模块 | 60mm 码的模块宽 | 100mm | 150mm |
|---|---|---|---|---|---|---|
| `https://lab.xxx.edu.cn/b2` | 25 | v4 | 41 | 1.46mm | 2.44mm | 3.66mm |
| `https://go.example.edu.cn/b2` | 28 | v4 | 41 | 1.46mm | 2.44mm | 3.66mm |
| 现状托管地址（带 sharecode） | 59 | v7 | 53 | 1.13mm | 1.89mm | 2.83mm |

**结论**：网址从 59 字符压到 25 字符，同样 60mm 的牌上模块从 1.13mm 变成 1.46mm，**扫码成功率明显提升**。这就是"用短链"的真正理由——不是为了好看，是为了模块够大。

## 四、为什么微信和系统相机都能打开

微信扫一扫、iOS 相机、安卓系统扫码，底层都实现同一个标准：**ISO/IEC 18004 的 QR Code Model 2**。所以只要码是标准二维码（不是 ArUco、不是自定义图案），两边都能解出同一个字符串。

差异只在**解开之后怎么处理**：

| | 微信扫一扫 | 系统相机 / 浏览器扫码 |
|---|---|---|
| 识别能力 | 标准 QR、条码 | 标准 QR、条码 |
| 打开方式 | **微信内置浏览器**（安卓 X5 / iOS WKWebView） | 系统浏览器（Safari / Chrome） |
| 额外检查 | 域名安全、备案、诱导行为 | 基本不检查 |
| 摄像头权限 | 受微信沙箱限制 | 系统原生 |

**所以两边都能开的前提只有三条**：码是标准 QR、网址是 https、页面能正常渲染。前两条由生成端保证，第三条是部署问题。

> 注意一个容易混淆的点：**"能打开页面"≠"页面功能可用"**。微信内置浏览器对摄像头、陀螺仪的权限比系统浏览器严。如果导航页依赖摄像头，微信内可能开得了页面但开不了相机——这属于功能层问题，见第八节的兜底设计。

## 五、微信内不被拦截的 7 个条件

这是整套方案里最容易翻车的地方。逐条对照：

| # | 条件 | 不合格的表现 |
|---|---|---|
| 1 | **HTTPS + 有效证书** | 提示「网页包含不安全内容」；证书过期直接白屏 |
| 2 | **域名已 ICP 备案**（境内服务器） | 「已停止访问该网页」 |
| 3 | **域名未被举报 / 不在黑名单** | 同上，且没有申诉入口 |
| 4 | **页面不诱导分享、关注、下载 App** | 被限制分享，或整页拦截 |
| 5 | **不强制跳转外部浏览器** | 被判「诱导跳转」 |
| 6 | **首屏体积小**（建议 < 1MB） | 加载卡死、白屏，尤其在弱网 |
| 7 | **托管平台要求分享码时，必须带全** | 「链接不完整，当前地址缺少访问参数」（我们踩过） |

第 7 条是我们已经踩过的坑：`.../fp-ar.html` 少了 `?sharecode=...`，微信能解出网址，但平台把它拦成了错误页。

**兜底设计（建议写进页面）**：如果检测到微信 UA 且摄像头不可用，不要弹窗拦截，只在页面上给一行**软提示**：「相机未能启动，可点右上角 ··· → 在浏览器打开」。硬跳转会被判违规，软提示不会。

## 六、生成与设计规范

### 6.1 生成参数

| 参数 | 取值 | 理由 |
|---|---|---|
| 纠错等级 | **H（约 30%）** | 永久码不重印，脏一点、缺一角也得能读 |
| 版本 | 尽量低（v4 以内） | 版本越低模块越大 |
| 静区 | **4 模块**（标准值） | 少于 4 模块，边上裁掉一点就解不出 |
| 颜色 | 纯黑 `#000000` + 纯白 `#FFFFFF` | 对比度必须 > 70% |
| 反色 | ❌ 禁止白码黑底 | 部分扫码器不支持反色 |
| 中心 logo | ❌ 禁止 | 永久码要留全部纠错余量，不要占用 |

### 6.2 尺寸怎么定

**规则：模块宽度 ≥ 1mm（推荐 1.5mm 以上），扫描距离 ≈ 码面宽 × 8~12。**

| 张贴位置 | 典型视距 | 建议码面（含静区） |
|---|---|---|
| 门牌旁 / 桌面 | 20–40cm | 50–60mm |
| 走廊墙贴 | 50–100cm | 80–120mm |
| 楼梯口 / 大厅海报 | 1–2m | 150–250mm |

> 注意：工具里 `--sizes 150` 指的是**含 4 模块静区的整体宽度**。150mm 的牌，二维码本体其实是 53 模块中的 45 模块 ≈ 127mm 见方。

### 6.3 张贴八条

1. 码中心高度 **1.40–1.65m**（对齐举手机的高度）
2. 贴在**与通行方向垂直**的墙面，视夹角 ≤30°
3. 正对来人的第一视线，不要贴侧面
4. 静区四周留 **≥5mm 纯白**，上面不要压字、不要压边框
5. 避开：门背后、门扇上、消防栓箱门盖、开关面板、强反光瓷砖对面、窗户正对（逆光）、洗手间外墙（潮气）
6. 不要用亮膜——反光会让整个码变成一块白
7. 建议每处贴 **2 张**（1.45m 主位 + 1.65m 副位）
8. 亚克力 UV 打印或 PVC 背胶；纸质 3 个月就卷边发黄

## 七、验证方法（三层，缺一层都不算验完）

### 第一层：印前数字自检

```bash
python tools/make_permanent_qr.py --url "https://go.xxx.edu.cn/b2" --sizes 60,100,150
python tools/check_qr.py qr_perm/code_150mm.png --spec qr_perm/spec.json --http
```

自检会报四件事：

- 解出的字符串是否与预期**完全一致**
- 静区是否达到 4 模块
- 模块宽度是否 ≥1mm
- 网址现在能不能打开（`--http`）

**这一步只能证明"文件是好的"，不能证明"印出来能扫"。**

### 第二层：印后实拍

打印一张，贴在目标位置，按这张表测：

| 变量 | 取值 |
|---|---|
| 手机 | 至少 3 台（iPhone + 安卓各一，再一台旧机型） |
| 扫码工具 | 微信扫一扫 + 系统相机，各测一遍 |
| 距离 | 30cm / 60cm / 100cm |
| 角度 | 正面 / 左右 30° |
| 光照 | 白天正常 / 走廊灯全开 / 只开应急灯 |

**判据**：3 台手机 × 2 个 App，在**设计视距内**全部能打开页面，算通过。有一台不行，就加大码面或换位置。

### 第三层：长期巡检

每学期一次，对着已贴的码跑：

```bash
python tools/check_qr.py 照片.jpg --expect "https://go.xxx.edu.cn/b2" --http
```

或者更省事：直接用手机扫一遍，重点确认**域名还在、跳转还在、页面还在**。域名到期和跳转失效是唯二会让"永久码"变废纸的原因。

## 九、必须接受的取舍

**单一永久码天然换不来"扫码即知位置"。**

因为位置信息必须一个点位一个值，而单一码所有地方都一样。所以：

- 想只印一种码 → 定位交给**页面内交互**（选楼层、选楼梯口），或者后续接别的定位手段
- 想扫码即知位置 → 必须每点位一张码，码里带点位 ID，那就回到"多码"方案

**这两件事不能同时要。** 选单一永久码，就是选"入口统一、定位靠用户点两下"。
