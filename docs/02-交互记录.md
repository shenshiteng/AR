### 做了什么

**技术选型（已定，后续沿用）**：纯静态 `index.html` + `data/labs.js`（JSON 套 `window.LAB_DATA=`）+ `js/router.js` + `js/app.js`，不用框架、不用打包。

**关键决定**：数据用 `<script src>` 引入而非 fetch，**保证双击 index.html 也能跑**（file:// 下 fetch 被 CORS 拦）。

**寻路**：全楼栋节点合成一张图，Dijkstra；跨层/跨楼用 `links`（type: stair / outdoor），文字提示按楼层高低自动判断"上/下"。

**ArUco 技术路线**（重要，别再走弯路）：
- ❌ 官网 opencv.js（10.9MB）**不含 aruco 模块**，grep "aruco" = 0 命中，不要用。
- ✅ 改用 **js-aruco2**（纯 JS，MIT）：内置 `AR.DICTIONARIES.ARUCO`（1023 号、25bit、tau 3）+ `AR.Detector`。
- 浏览器里 `this.CV` 生效，不需要 require；先加载 cv.js 再加载 aruco.js。
- `new AR.Detector({dictionaryName:'ARUCO'})` **必须显式传字典名**（默认 'ARUCO_MIP_36h12' 不存在会抛错）。
- **自带的 `dictionary.generateSVG(id)` 有 off-by-one（画的格子偏一格），别用**；自己按 `codeList[id]` 的 25 位串画 7×7。

**方向算法（和文档的差异，已向用户说明）**：
文档说"读码的偏转角度→手机朝向"，物理上单个平面码只能算滚转角，算不出真朝向（要 POSIT+内参）。
实际实现：**扫码位置 + 墙面法线 normal + 罗盘（可选）**。
- `facing = normal + 180`（人站在码前、面朝墙）
- `rel = norm(图像角(起点→第一拐点) - facing)`；罗盘开了则 `rel = norm(罗盘方位(目标) - heading)`
- 图像角 0=东、90=南、270=北；`toCompass(a)=(a+90)%360`（**注意入参已是角度不是弧度，曾写成 deg(a) 出过 bug**）

**接入真实疏散图的结论**：这类"拍照的疏散图"自动识别**只能做到一半**。
- 全局阈值完全失效（纸面背景灰度 150~190、红线 110~140，且有光照渐变）→ 加**自适应阈值**（积分图算局部均值）
- 加了自适应也要**先裁剪到图纸内部**（x20,y240,1750×1660）才有效
- 最终 seal=34 / thr=140 能出 23 个框，但小房间抓不到、部分被拆成两块、混进图例框
- **文字完全认不出**，必须人工补

→ 结论：识别只能当"辅助框选"，真正的语义还得人读图。实际做法是**手工建层**：环形走廊（上 420 / 左 288 / 右 1118 / 下 1542）+ 28 节点 28 边 + 36 间房。

## 2026-10-21 · AR 导航改成「实时步行跟踪」

### 用户要什么

用户拿手机实测后反馈（附截图）：**现在的箭头只是扫码那一刻的方向，不是实时跟踪**。
他要的是高德地图 AR 步导那种：人走到哪、箭头指到哪。

### 根因

原实现 `updateView()` 用 `state.facing`（扫码瞬间的朝向）+ 固定起始节点算方向，从来没动过。

### 新内核（`js/ar.js`）

室内没有 GPS，只有两个真实信号：
1. **罗盘 DeviceOrientation**（60Hz）→ 手机朝向
2. **加速度计 DeviceMotion** → 峰值检测计步 → 步数 × **0.72m** = 走了多远

位置用「沿路线里程」`track.pos` 表示：
- `buildTrack(route)` 把路线折线转成里程表 `segs[{a,b,len,cum0,ang}]`
- `pointAt(pos)` → 坐标插值
- `planAt(pos)` → 当前段、到下一个拐点的距离、转角
- `advance(stepLen)` → 计步推进 → `updateView()` 全量重算

### 方向算法（踩过两个坑，别再走回头路）

- ❌ 坑1：转弯时 aim 指向「拐后那一段的末端」。支廊段只有 4.4 米，从走廊上指过去是**斜角**（算出 129° 而不是 90°），箭头歪 20~30°。
- ❌ 坑2：改成 look-ahead 取 pos+8 米的点。方向一样是斜的，而且**提前 8 米就开始偏**（北走廊段长才 5.4 米）。
- ✅ 最终：**用「段的方向」而不是瞄点**。`aimAngle(pos)` = 当前段的 `ang`；到拐点距离 ≤ `TURN_LEAD(3m)` 时提前切到拐后那段的方向。

### 罗盘处理（多个坑）

- `requestSensors()` 必须在**用户手势**里调（iOS 13+ 的 requestPermission 两个都要）→ **深链漏了会导致整个跟踪不生效**（踩过）。
- 低通平滑 `compass = compass + norm(h-compass)*0.45`。
- 磁干扰过滤：间隔 <120ms 且跳变 >45° 的帧直接丢。
- 渲染节流：变化 <1° 不重画。
- **bug**：`onOrient` 里 `if(!compassOn) compassOn=true`，用户手动关罗盘后下一帧又被打开 → 加 `compassWanted` 标志区分"用户想要"和"有数据"。
- 关罗盘时**不要清空 `state.compass`**，保留最后值。

### 两条硬教训

1. **室内罗盘绝对方位偏约 80°**，只能取增量（`baseFacing=normal+180`，罗盘方位 = 图像角+90）。
2. **防磁过滤缺逃逸口会永久卡死**（加连续 5 帧一致放行）。

### UI

- `.trackbar`：`已走 X 米 / 还剩 Y 米` + 进度条 + `计步 N 步` + `−5米 / +5米` 手动修正（**PDR 有累积误差，必须给人纠偏手段**）
- `.guide` 地面引导带：clip-path 梯形 + 条纹 mask
- `.arrowwrap.arrived` 到达态：箭头淡出、大字「已到达」、振动 `[70,60,70]`
- 距拐点 ≤5 米振动 40ms（`warnedTurn` 防重复）
- 文案：>3m「走约 X 米到「拐点名」，然后左转」；≤3m「再走 X 米就左转」；<1m「就是这儿，左转」

### 踩的坑：缓存错配导致"教室全搜不到"

`flipBtn` 为 null → TypeError → 搜索框未绑定。修法：判空 `on/txt/cls` + 搜索框绑定提前 + `?v=6`。

### 验证方法（可复用）

CDP（端口 9231）里手工派发事件，比真机快：
```js
// 罗盘：alpha=270 → heading=90（面朝东）
window.dispatchEvent(Object.assign(new Event('deviceorientation'), {alpha:270, absolute:true}));
// 计步：低谷 9.0 / 峰值 12.8 交替，间隔 280ms
window.dispatchEvent(Object.assign(new Event('devicemotion'),
  {accelerationIncludingGravity:{x:0,y:0,z:12.8}}));
```

### 做了什么

**`renderAr` 改成三态**：

**新增 `#buildingSel` 楼下拉**（数据源 `LAB_DATA.buildings`）；`fillFloors/fillStairs/fillDatalist` 改为按 `curBuilding` 过滤；选楼自动切该楼第一层。

### 关键决策

**桥接对象必须让名**：js-aruco2 的全局对象恰好也叫 `AR`，IIFE 内 `AR` 遮蔽全局 → `new AR.Detector(...)` 抛 "not a constructor" 被 try/catch 吞掉，误报"识别库没加载"。

**自动化参数宁可降级成预填，也不要抢跑**：凡用户明确要求"默认安静/等待"的功能，URL 参数只做预填。

### 踩的坑

- 排查时用 `page.evaluate(() => typeof AR)` 在顶层作用域检查，看到的是识别库的 AR（正常），**没进页面 IIFE 作用域查**，因此没发现遮蔽。
- 之前只测"页面能跑、导航逻辑对"，**没真正端到端触发扫码→定位链路**（无头浏览器没摄像头就一直没测）。
- 测试脚本自身犯两个错，白查两轮：画布 280px 装不下 7×40=320px 的码被裁掉；sed 只替换 `var cell` 没替换 `const cell`。

### 立下的规则

**新建顶层变量前先 grep 检查是否与第三方库全局名冲突。**
已占用全局名单：`THREE, AR(js-aruco2), LAB_DATA, FLOOR_GRID, FLOOR_WALLS, FLOOR_*_*, FPWorld, FPView, FPInput, FPValidate, LabRouter, ArucoMark, __FP__, __AR__, __arDebug`
（`__AR__` 是自有桥接口，`AR` 是识别库的——差一个下划线，极易混）。

**修"某功能不工作"的 bug，必须在触发该功能的真实代码路径上做端到端验证；测试不过先怀疑测试脚本本身。**

- 改 `sw=340→480` 后系数 0.135，同一块码距离 ×1.5

**页面尺寸上限**：静区需 1 格 = 码面/7，故 `W ≤ 7A/9`（A4 可用 186mm → 145mm；A5 128mm → 99mm；A3 267mm → 207mm）。

**字典实测**：1023 个码，全字典最小汉明距离 **3**；ID 0 与 1 只差 3 位，正好是 3 层东北/西北楼梯口。
贪心筛选 **116 个码可达最小距离 6**（7 位凑不够）。

**门牌码精度坑**：104 个 `labs[].door` 中 **81 个房间挤在 30 个门口路点**（最多 6 间共用一个点）；
**30 条记录与楼梯口定位点重合** → 门牌码只能做到「我在这一片」，误差 1–3 米。

**二维码纠错的反直觉**：ECC 从 M 提到 Q 会让码从 41×41 涨到 45×45 模块，同尺寸下模块反而变小
→ **扫不出时优先放大码面，别降纠错**。

**融合码结论**：技术上成立（一张码 OpenCV 解出网址 + js-aruco2 认出 ArUco ID）；
- 纠错 **M 会直接废掉二维码**，必须 ≥ Q
- **静区 1 格优于 2 格**（与"建议 1.5~2 格"的代码分析结论相反）
- v2 放不下，甜点区 **v4~v5**
- 两边同时可读需 **200px 画面宽**（最差 240px），瓶颈在 ArUco
- 可用距离 ≈ 码面宽 × 1.0~1.3（sw=340）；改 sw=640 后 ×1.88
- **融合码 A4 只有双码方案的 1/3**

**码制验证结论**：单张标准 QR 不能同时满足「微信扫码 + 6DoF 位姿」——
QR v7/H 有 53 模块需 ~2.5px/模块 = 133px 投影宽，AprilTag 36h11 只 10 模块，
**像素预算差 3.3 倍，无法靠调参弥补**。
匹配工况下 AprilTag 误差始终更小：400mm@3m **42.8 vs 7.4mm**（差 5.8 倍）。
遮挡与直觉相反：QR 能忍 8%（Reed-Solomon），AprilTag 只忍 5%，
**失败点在检测阶段的黑边框被破坏** → 施工要点：**黑边框比内部数据更脆弱**。

**形态结论**：**小程序为目标形态**（ArUco 须在应用内扫，"应用怎么打开"成第一问题；
小程序能从「最近使用」一步打开 + 常驻自动扫）；APP 不推荐；个人主体可行（工具类类目、去机构化命名、同样需 ICP 备案 7–15 工作日）。

### 关键决策

**三维空间 = 二维矩形数据 + 高度拉伸**，不是建模软件做的。

**「像那张图」的关键是正交相机**：`OrthographicCamera` + 相机在 (1,1,1) 方向，
`polar = atan(√2) = 54.74°`（俯角 35.26°）、`azim = 45°`；**透视相机永远做不出这种比例**。

**3D 参数（关键，别乱改）**：
- **墙高 1.8m**（试过 3.4 / 2.2 都不行，走廊只有 2m 宽，墙再高绿色路线被完全遮住）
- **俯角 42°（`polar = 0.838`）**（标准等轴测 35.26° 在窄走廊下同样被遮，42° 是能看清路线的最小值）
- 路线管道半径 0.42m、抬高 0.55m；门洞宽 2.4m

**房间坐标提取方法**（已验证有效，**直接连通域/Hough 都不行**）：
**按行带/列带分区投影** —— 先全局行投影找关键横墙，再对每个行带做列投影（阈值取带高的 **0.7**）找竖隔墙，
反向做行投影得横隔墙（**文字笔画只有 50~60px，区分度极高**）；
颜色掩膜用 **Lab 的 a 通道 > 138**，比 HSV 稳；结果必须**叠加回原图画核对图**再定稿。

**寻路**：内置 A*，房间矩形栅格化成 **6px 网格**，障碍外扩 **9px（PAD）**；出来后视线抽稀保留拐点，再倒圆角 + TubeGeometry。

**单文件打包的理由**：问题不是文件缺失，是**路径越界** —— `../js/vendor/three.min.js` 跳到 `nav3d` 目录外，
双击 file:// 能开，但预览面板/单独分享只托管单个 HTML 时跳不出去。
