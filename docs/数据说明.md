# 数据说明（data/labs.js）

`data/labs.js` 里整个内容就是一段 JSON，外面套了一层 `window.LAB_DATA = { ... };`。
**格式很严格**：不能有注释、最后一项不能多逗号、字符串必须用双引号。改完保存，刷新页面即可。

> 用 `tools/marker.html` 生成楼层部分最稳：**选完平面图会自动识别**房间框、走廊路点和连线，确认后一键导出；手写容易漏逗号。

## 整体结构

```js
window.LAB_DATA = {
  site: "示例大学 · 材料与化学实验楼群",  // 页面左上角显示的名字
  metersPerPixel: 0.05,                  // 图片 1 像素 = 多少米（决定距离算得准不准）
  buildings: [ ... ],                    // 楼栋
  floors: [ ... ],                       // 楼层（含平面图、房间、可走的路）
  links: [ ... ],                        // 跨楼层 / 跨楼栋的通道
  labs: [ ... ],                         // 实验室（可被搜索的实体）
  locations: [ ... ]                     // 定位点（对应一个二维码）
};
```

---

## buildings 楼栋

```js
{ "id": "A", "name": "A栋", "desc": "材料楼" }
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一编号，`floors.building` 要引用它 |
| `name` | 显示名，会出现在筛选条和指路文案里 |
| `desc` | 副标题，如"材料楼" |

---

## floors 楼层

```js
{
  "id": "A-2",                       // 楼层唯一 ID，全文引用都用它
  "building": "A",                    // 属于哪栋楼
  "name": "2层",                      // 显示名
  "image": "assets/floors/A-2.png",   // 平面图路径；留空 "" 则自动画示意图
  "width": 1000,                      // 坐标系宽度 = 图片像素宽度（留空图时自己定）
  "height": 640,
  "nodes": [ ... ],                   // 可走的点
  "edges": [ ... ],                   // 点与点之间的路
  "rooms": [ ... ]                    // 房间（只用来画图和高亮）
}
```

### nodes 节点（最重要）

```js
{ "id": "A-2/n3", "x": 380, "y": 300, "note": "走廊中段" }
```

| 字段 | 说明 |
|---|---|
| `id` | 必须全局唯一，建议 `楼层ID/n序号` |
| `x` `y` | 在平面图上的像素坐标（左上角为 0,0） |
| `note` | 这个点的"人话"名字，**会直接出现在指路文案里**，如"楼梯电梯厅""走廊尽头" |

**铺节点的原则**：走廊每 3~5 米一个；每个楼梯口、每个岔路口各一个；房间门口对应走廊上的一个点（就是实验室的 `door`）。

### edges 路

```js
["A-2/n1", "A-2/n2"]           // 距离自动按像素算
["A-2/n2", "A-2/n3", 8.5]      // 也可以手动指定米数（第三个值）
```

同一层内可以简写成 `["n1", "n2"]`，程序会自动补上楼层前缀。

### rooms 房间（房间主表：点图查询、筛选、导出台账都用它）

```js
{ "id": "A201", "name": "3D打印实验室", "x": 60, "y": 50, "w": 200, "h": 150, "kind": "lab" }
```

| 字段 | 说明 |
|---|---|
| `id` | 房间号，实验室的 `room` 引用它。**必须唯一** |
| `name` | 房间名称，显示在地图框和信息卡上 |
| `x` `y` `w` `h` | 方框位置和大小（像素） |
| `kind` | 房间分类（见下方分类字典），供分类筛选和导出台账用 |
| `area` | 可选，面积（㎡）。不填时按 `w×h×metersPerPixel²` 自动估算 |
| `desc` | 可选，描述文字，点图信息卡里显示 |
| `tags` | 可选，搜索词数组 |

**分类字典（kind）**：

| 值 | 含义 | 地图颜色 |
|---|---|---|
| `lab` | 实验室 | 蓝 |
| `office` | 办公室（院长/教授/团委/教研室等） | 青 |
| `room` | 其他房间（会议室/资料室/活动室等） | 紫 |
| `store` | 库房/储物间 | 黄 |
| `service` | 设备用房（配电间等） | 灰 |
| `toilet` | 卫生间 | 绿 |

> 注意：`labs[]` 里引用的每个 `room` 号，都应该在 `rooms[]` 里有对应条目，
> 否则搜索能搜到但在平面图上定位不到（孤儿引用）。首页的「楼层平面图」支持
> 点房间看信息卡、按分类筛选、按房间号/名称搜索定位，以及一键导出房间台账 CSV。

## links 跨层、跨楼通道

```js
{ "from": "A-1/n6", "to": "A-2/n6", "type": "stair", "meters": 12 }
{ "from": "A-1/n1", "to": "B-1/n1", "type": "outdoor", "meters": 90 }
```

| 字段 | 说明 |
|---|---|
| `type` | `stair` 楼梯/电梯（文案自动判断"上到/下到"）、`outdoor` 室外道路（文案自动拼楼栋名） |
| `meters` | 走这段折算多少米。上下一层建议 10~15（含找楼梯的时间） |

> 注意：`type: "stair"` 的两端节点必须是**两层的楼梯口节点**，否则路线会穿墙。

## labs 实验室

```js
{
  "id": "L-A201",
  "name": "3D打印实验室",
  "floor": "A-2",
  "room": "A201",          // 对应 rooms 里的 id
  "door": "A-2/n2",        // 门口最近的节点；不写就自动取房间中心最近的点
  "tags": ["3D打印", "增材制造"],
  "desc": "FDM / SLA / SLS 打印设备与后处理工位",
  "phone": "内线 6201"
}
```

搜索会匹配 `name + room + tags + desc`，所以**用户可能搜的词都往 `tags` 里塞**（俗称、设备名、研究方向都可以）。

## locations 定位点（= 一个二维码 / 一个 ArUco 码）

```js
{ "id": "P-A1-01", "floor": "A-1", "node": "A-1/n1", "place": "A栋 1层 · 大门内侧", "marker": 0, "normal": 90 }
```

| 字段 | 说明 |
|---|---|
| `id` | 二维码参数，扫码后 URL 是 `?loc=P-A1-01` |
| `node` | 这个码贴在哪个节点上（决定"你在这里"的起点） |
| `place` | 页面上显示的位置描述，**写得越具体越好**，如"B栋 2层 · 电梯出来右手边" |
| `marker` | ArUco 码编号（0~1022），打印页和扫码都按这个号对应。**不能重复** |
| `normal` | 贴纸正面朝向的方位角（图上方为北：0=东、90=南、180=西、270=北）。AR 页靠它算"左转还是右转" |

> `normal` 怎么填：它表示**贴纸正面朝哪边**（贴纸像块牌子，正面朝着人）。
> 方位约定：图上方为北，`0=东、90=南、180=西、270=北`。
> 例：贴在走廊**北墙**上、正面朝南对着走廊 → `normal = 90`；贴在**南墙**上、正面朝北 → `normal = 270`。
> 拿不准就统一填 90，然后现场试一次：如果"左转/右转"反了，把 90 改成 270。

加完定位点后重新运行：

```bash
python tools/make_qr.py
```

## 自检清单

改完数据，打开页面看这几件事：

- [ ] 实验室列表全部出现，没有"暂不可达"
- [ ] 从每个定位点出发，去最远的实验室，路线不穿过墙
- [ ] 跨层的步骤写的是"上到"还是"下到"，方向对
- [ ] 距离数量级合理（走廊一眼能判断：房间长度 5 米还是 50 米）
