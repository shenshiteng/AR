# ArUco × 二维码 融合码 · 实验结论

> 实验日期：2026-11-06  
> 目标：做一张**同时能被两种解码器读出**的码——微信扫出网址，页面里的 js-aruco2 认出定位码  
> 工具：`tools/make_hybrid.py`（生成）、`tools/verify_hybrid.py`（验证）、`tools/aruco_probe.js`（Node 侧跑真 js-aruco2）

---

## 一句话结论

**技术上成立，实测能同时读出。但有个硬代价：ArUco 只有二维码宽度的 14–17%，导致可用距离比"两个码"方案短一半以上。**

- A4（186mm）在现状检测分辨率下只有 **20–24cm**，需要贴到脸上才扫得到
- 把 `fp-ar.html:452` 的 `sw = 340` 改成 `640`，同样一张 A4 变成 **38–46cm**
- A3 + `sw=640` 是 **55–66cm**，这时才接近双码方案的水平

---

## 一、发现在我意料之外的三件事

### 1. 纠错等级 M 会直接把二维码废掉

`hy_mid_m_q2`（v4 + M + 2 格静区）这一组，**二维码在所有退化条件下都解不出**，连原图都不行。原因：9~11 格的挖空损坏的码字数量超过了 M 级（15%）能补回的上限。

**结论：融合码的纠错等级必须 ≥ Q（25%）。M 不要试。**

### 2. 静区 2 格反而更差

| 静区           | 损坏面积   | 结果          |
| ------------ | ------ | ----------- |
| 1 格（9×9 块）   | 81 模块  | ✅ 小版本也能用    |
| 2 格（11×11 块） | 121 模块 | ❌ v3、v4 直接废 |

代码分析时说"1 格是下限，建议 1.5~2 格"，实测反过来：**1 格就够，2 格会拖垮二维码**。因为 ArUco 的黑框本身就提供了清晰的轮廓边界，不需要那么多白边。

### 3. 网址越短 ≠ 越好，v2 根本放不下

短链（20 字符）会生成 v2（25×25 模块），这时**连 9×9 的干净区域都找不到**——三个定位图案、时序线、对齐图案把地方占满了。

| 版本 | 模块数   | 能放下 ArUco 吗          |
| -- | ----- | -------------------- |
| v2 | 25×25 | ❌ 放不下（9×9 都不行）       |
|    |       | ⚠️ 只能 1 格静区，且 QR 容易废 |
|    |       | ✅ 最佳（ArUco 占 17.1%）  |
| v5 | 37×37 | ✅ 占 15.6%            |
| v6 | 41×41 | ✅ 占 14.3%            |
| v8 | 49×49 | ✅ 占 12.3%            |

**所以有甜点区：v4~v5。太短放不下，太长 ArUco 变小。**

## 二、实测数据

测试条件：旋转 4° + 高斯模糊 σ=0.9 + 噪声 σ=6 + JPEG 55，模拟手机在远处拍照。4 个随机种子取最差。

| 配置                    | 版本 | 总模块 | ArUco 占宽 | 两边同时可读的最小画面宽                   |
| --------------------- | -- | --- | -------- | ------------------------------ |
| 70 字符（现状，带 sharecode） | v6 | 49  | 14.3%    | **240px**（4 次：240/170/170/170） |
| 48 字符（去掉 sharecode）   | v5 | 45  | 15.6%    | **200px**（4 次：200/170/200/170） |
| 38 字符（短路径）            | v4 | 41  | 17.1%    | **200px**（4 次：140/200/200/170） |

**波动说明**：同一张码，只换噪声种子，极限就从 140 跳到 240px。因为挖空落在哪个码字上是随机的，运气好只损坏几个、运气坏损坏一串。**做设计要按最差值算，不能按最好值。**

分项极限（严苛档，v5/Q/1 格静区）：

| 项目       | 最小画面宽 | 折算每格像素    |
| -------- | ----- | --------- |
| 二维码单独    | 170px | 3.8 px/模块 |
| ArUco 单独 | 200px | 4.4 px/格  |

**瓶颈在 ArUco，不在二维码**——这跟直觉相反。因为 ArUco 虽然只要 7 格，但它紧挨着二维码的噪点，轮廓检测更吃力。

---

## 三、能扫多远的换算

`js-aruco2` 检测时把画面压到 **340px 宽**（`fp-ar.html:452`）。设码面物理宽度 W（mm）、距离 d（mm）、手机水平视野约 66°（视野宽 ≈ 1.3d）：

```
dmax ≈ 340 × W ÷ (1.3 × 200~240)
    ≈ W × 1.0 ~ 1.3
```

| 码面（含 4 模块静区） | 现状 sw=340   | 改 sw=640 |
| ------------ | ----------- | -------- |
| A4　186mm     | **20–24cm** | 38–46cm  |
| A3　267mm     | **29–35cm** | 55–66cm  |
| A2　380mm     | **41–50cm** | 78–94cm  |

对比双码方案（ArUco 单独印 120mm）：**60cm**。所以：

> 融合码在 A4 上只有双码方案的 1/3 距离；要做到 A3 + 改分辨率，才能打平。

| 项目                        | 结果                                |
| ------------------------- | --------------------------------- |
| 12 个 marker 号（0~11）各自认对   | ✅ 全部正确，无互相混淆                      |
| 纯二维码会不会被误认成 ArUco         | ✅ 零误报（三个定位图案虽然几何同构，但汉明距离远超 tau=3） |

| JPEG 35                   | ✅ 两边都过                            |
| 对比度降到 0.55                | ✅ 两边都过                            |

## 五、推荐参数

```
网址     必须带 sharecode；用根路径写法（59 字符 → v5，ArUco 15.6%）
         想再大一点只能等平台支持短链（≤46 字符 → v4，ArUco 17.1%）
纠错     Q 或 H（绝不用 M）
静区     1 格（不要 2 格）
码面     A3 起（A4 太勉强）
检测     sw 340 → 640（改 fp-ar.html:452 一行）
```

生成命令：

```bash
python tools/make_hybrid.py \
  --url "https://lab-ar-nav.app.workbuddy.host/?sharecode=COAQ2BOKWL" \
  --marker 2 --ecc q --quiet 1 --px 20 --mm 267 --name hy_A3_P-B2-03
```

产物：`hybrid/hy_A3_P-B2-03.png`（屏幕预览）+ `hybrid/hy_A3_P-B2-03_267mm.png`（300dpi，直接送打印店）。

### 踩过的坑：网址必须带 sharecode

第一次出的样张网址是 `.../fp-ar.html`（48 字符）。微信能扫出网址，但打开后显示「链接不完整 / 当前地址缺少访问参数」——托管平台的分享码是硬门槛。

正确写法（59 字符，比完整路径短 10 个字符，**ArUco 反而更大**）：

```
https://lab-ar-nav.app.workbuddy.host/?sharecode=COAQ2BOKWL
```

根路径能用，是因为 `index.html` 第 13 行会把查询参数原样转发：
`location.replace('fp-ar.html' + '?' + qs + '&from=index')`。

| 写法 | 字符数 | QR 版本 | ArUco 占宽 |
|---|---|---|---|
| `.../fp-ar.html`（无 sharecode，**不可用**） | 48 | v5 | 15.6% |
| `.../?sharecode=COAQ2BOKWL`（**推荐**） | 59 | v5 | 15.6% |
| `.../fp-ar.html?sharecode=COAQ2BOKWL` | 69 | v6 | 14.3% |

> **风险提醒**：sharecode 是托管方案的固定凭证。一旦应用重新发布导致它变化，**所有已印的融合码全部作废、必须重印**。这是融合码的隐藏成本——双码方案只需重印那小块入口码，ArUco 不用动。

**下一步必须做的**：把 `hybrid/hy_A3_P-B2-03_267mm.png` 打印出来贴墙上，用 3 台不同手机测「页面里对准能不能认出 ID」。**这一步不做，距离数据都只是参考。**

## 七、和双码方案怎么选

|        | 融合码（一张）                       | 双码（大 ArUco + 小 QR） |
| ------ | ----------------------------- | ------------------ |
| 学生要扫几次 | 1 次（微信扫完直接进页面，页面自动认中间的 ArUco） | 2 次（微信扫小码进站，再对准大码） |
| 牌面尺寸   | 至少 A3                         | A4 就够              |
| 可用距离   | A3+sw640：51–66cm              | A4：60cm            |
| 换域名    | 全部重印                          | ArUco 不用重印，只换入口小码  |
| 印刷容错   | 低（一块脏就两边都废）                   | 高（两个码各自独立）         |
| 制作成本   | 一张图，一个文件                      | 一张图，两个码            |

**建议**：

- 想少扫一次、能接受 A3 和改一行代码 → 用融合码
- 想稳妥、想省地方、想以后好维护 → 用双码

两条路都已经有工具了，不冲突。
