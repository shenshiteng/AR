## 01. 项目是什么

**不用装 App、没有后端**的室内导航系统：走廊贴二维码（或 ArUco 码）→ 手机扫码 → 页面知道"你在哪个楼梯口" →
选目的地 → 出路线、分步文字指引、AR 箭头，外加一个可交互的三维沙盘。

现在装的是**第二实验楼 2 / 3 / 5 层**的真实数据（**没有 1 层和 4 层**）：1 栋楼 / 3 层 / 104 个实验室 / 12 个定位点。
平面图 = 那几张应急疏散图（拍照/扫描件）。

**技术栈**：纯前端原生 JS，ES5 风格（IIFE + `'use strict'` + `var` + `window.X` 全局 + 中文块注释），
无框架、无打包器。三维用 three.js r128（离线内置）。数据是"JSON 穿 JS 马甲"，走 `<script src>` 加载。

### 4.3 字段定义

```js
// floors[]
{ id:"B2-3", building:"B2", name:"3层", image:"assets/floors/B2-3F.jpg",
  width:1540, height:1560, nodes:[], edges:[], rooms:[] }

// nodes[]  坐标 = 图片像素，原点左上，x 向右、y 向下

// edges[]  同层可简写 "n1"，程序自动补楼层前缀；第三项可手动给米数
["n1","n2"]  |  ["B2-2/n1","B2-3/n1",8.5]

// rooms[]
{ id:"316", name:"配电间", kind:"service", x:270, y:20, w:90, h:200,
  area?, desc?, tags? }

// labs[]
{ id:"L316", name:"配电间", floor:"B2-3", room:"316", door:"B2-3/n17", tags:["配电"], desc?, phone? }

// links[]
{ from:"B2-2/n1", to:"B2-3/n1", type:"stair", name:"西北楼梯间", meters:8 }

// locations[]
{ id:"P-B2-01", floor:"B2-3", node:"B2-3/n3", place:"3层 · 东北楼梯口（324旁·疏散图旁）",
  marker:0, normal:0 }
```

**`kind` 字典**：`lab` 实验室(蓝) / `office` 办公室(青) / `room` 其他房间(紫) / `store` 库房(黄) /
`service` 设备用房(灰) / `toilet` 卫生间(绿) / `stair` 楼梯间。

**`normal` 方位约定（最重要）**：图上方为北，**0=东、90=南、180=西、270=北**（顺时针）。
它表示**贴纸正面朝哪边**。扫码那一刻的绝对朝向 = `normal + 180°`（人总是面朝贴纸站）。
朝向 `theta` 用同一套约定（0=东 +x、90=南 +y、180=西、270=北）。

## 06. 关键算法（改之前必须懂）

### 6.1 寻路（`js/router.js`）
- Dijkstra，边权 = 像素距离 × `metersPerPixel`；第三项显式米数优先。
- 同层 `edges` 可简写 `"n1"`，`node_of()` 自动补楼层前缀（`router.js:34-36`）。
- 跨层走 `links`，`type:"stair"` 自动判"上到/下到"（比 `floors` 顺序），`outdoor` 拼楼栋名。
- 时间 = 总距离 ÷ 60 米/分钟（室内步速）。
- **"兜底换面"是寻路的万恶之源**：宁可报"不通"，也不许偷偷换一条不该存在的路。

### 6.2 AR 朝向（`fp-ar.html` + `js/ar-bridge.js` + `js/ar.js`）
一句话：**绝对朝向来自墙上的贴纸，罗盘只负责"你转了多少度"。**

1. 扫码那一刻人必然面朝贴纸 → 绝对朝向 = `normal + 180°`（来自图纸，不受现场磁场影响）。
2. 之后转身，罗盘只取**转角增量**，加到绝对朝向上。
3. 目标方向 = 当前位置的路线走向；两者相减 → 直行 / 稍向左(右) / 左转(右) / 掉头。
4. **不直接用罗盘绝对方位**：室内钢结构/配电箱/管道把磁场扭曲，实测这栋楼偏约 80°；
   但"转了 90°"这个增量是准的（偏差恒定，做差抵消）。

**罗盘处理**：单帧跳变 > 45°/120ms 的读数直接丢（防乱甩）；连续读数低通平滑（防手持抖动）；
**只用增量不用绝对值**。曾因"快速转身被过滤器永久丢弃"导致该拐不拐，已修。

### 6.3 计步（实时步行跟踪）
- 罗盘（DeviceOrientation，60Hz）→ 箭头跟转；加速度计（DeviceMotion）→ 迈步峰值计步。
- 位置用"沿路线的已走米数"表示：每步 +0.72 m → 重算在第几段走廊 / 下一个拐弯还有多少米。
- 进入拐点前 6 米箭头开始平滑偏；6~3.5 米显示"前方左转 · 还有 5 米"；3.5 米内变"左转 52°"；
  路口显示"就是这儿，左转"；距拐点 ≤5 米振动。
- 步长误差累积（走 70 米可能差 5~8 米），界面上有 `−5 米 / +5 米` 手动修正；走到下一个码再扫一次最准。
- 罗盘可关：退回"扫码瞬间锁定朝向"静态模式。方向整体反了 → 点「⇄ 反了」翻 180°。

### 6.4 墙清理（`tools/grid_to_js.py` 内置，用户拍板最终版）
1. **闭运算合并平行细线**（`close-cells=1`，合并间隔 ≤8px）—— 消灭第一人称里的"平行栅栏"。
2. **只删房间矩形深处的墙**（`interior-margin-px=8`）。
3. **路网保路**：`nodes+edges` 连了边的走廊，边线两侧 `corridor-half-px=12px` 内的墙格一律挖掉 ——
   "数据说能走就保证不挡"，节点落墙问题也随之解决。
4. 被删墙在俯视总览用黄色标出供核对。
5. **判定墙的准绳**：真实墙 = 房间框边线 + 楼外轮廓；房间内部与走廊中间的细条多是照片噪声。

### 6.5 楼梯（双跑折返）五条硬规则（2026-10-30 定，改动前先读）
1. **换层只认"上一层地面"**：`checkStairTransition` 阈值 `|z| ≥ 层高 − 0.02`。
   半层高(1.5m) 是**中间平台**，只转弯、绝不换层（曾用 0.499×层高 → 一上平台就变三层）。
2. **平台转弯的目标角必须每帧按当前位置重算**，锁死一次会"已转到位但永不满足放行"的原地死锁。
3. **坡度参数化按"可走范围"归一**，不是房间矩形：`pad=min(20, L*0.25)`（墙厚+玩家半径 12px）、
   `buf=min(10, span*0.3)`，`t` 在 `[pad+buf, L-pad]` 映射（0=进门平地末端，1=远端墙）。
   按矩形算，60~70px 的小楼梯间永远走不到平台。
4. **一份几何只留一个出处**：`axis/dir/pad/buf/plat` 全放 `world.stairs`（fp-core 生成），
   高度场 / 3D 台阶 / 页面转弯判定全读它。谁再"猜门在哪一侧"必然漂移。
5. **门侧用跨层边上的楼梯口节点判定**（`buildWorld` 传 `stairDoors`）。用"离房间中心最近的路点"会判错：
   东南/西南楼梯间的门在正南，斜上方走廊节点却更近。窄楼梯间跑道中心夹 `LANE_MARGIN=24`。

### 6.6 三维沙盘的路网模型（`nav3d/tools/check_grid.py`）
- **楼板只存在于 `corridors` + `spurs` 上，其余全挡**（不许"默认全图可走"，大图上必然穿墙）。
- 房间靠"门点外 44px 落在走廊里"判通 → **走廊必须盖住每个门点**
  （例：北排房间门 S → 门点 y442+44=486，走廊 y442-495 必须覆盖 486）。
- 连通块数必须 = 1，否则该层一定有点不动的房间。

### 6.7 三维页面参数（别乱改）
`pxPerMeter=26`；墙体高度、等轴测相机、`focus(id)` 取景接口在 `_dev.html` 里；
自检入口 `?noauto=1&selftest=1`，单间排查 `?probe=<房间ID>`。
套间（334/335 via 333、234/235 via 233）必须同时满足：① 宿主可达 ② 门开在与宿主共用的那道墙上
且落在宿主跨度内 ③ 自己那道门不许直通公共走廊。

## 08. 踩坑清单（必读，勿再犯）

### 8.1 全局命名冲突（2026-10-26，最贵的坑）
js-aruco2 的全局对象叫 **`AR`**。页面脚本里绝不能再定义 `var AR`（曾把桥接模块命名 AR，
遮蔽识别库 → 扫码报"识别库没加载"）。桥接模块现名 `Nav`（页面内）/ `window.__AR__`（全局）。
**新起变量名前先 grep 全局名单**：`THREE` / `AR` / `LAB_DATA` / `FLOOR_*` / `FPWorld` / `FPView` /
`FPInput` / `FPValidate` / `LabRouter` / `ARBridge` / `ArucoMark` / `FloorDetect` / `FloorImport` /
`__FP__` / `__AR__` / `__arDebug`。

### 8.2 功能修复必须端到端验证真实触发路径
无头浏览器可用「`canvas.captureStream()` 伪造摄像头 + 画布画 ArUco 码 + `addInitScript` 覆盖
`getUserMedia`」完整测扫码定位链路（2026-10-26 日志有模板）。

### 8.3 测试失败先怀疑测试脚本本身
尺寸裁切、sed 替换漏 `const`、`--virtual-time-budget` 卡住等都发生过。

### 8.4 手机端摄像头/罗盘必须 https
`isSecureContext` 为假时要**在页面横幅明说原因**，绝不静默 catch。

### 8.5 ArUco 码生成
1. **画图逻辑写反 → PNG 全纯黑块**：先画 7×7 大黑框后，应画 `'1'` 白格（fill=255）挖出图案；
   写反成画 `'0'` 黑格（本来就黑=没画），结果码区一整块黑、12 张全一样。
   生成后自查"图里是否真有图案"（黑像素占比是否随码不同而变）。
2. **别手写 BMP 冒充 PNG**：用 PIL 生成真 PNG。
3. **自检要验"最终产物"本身**：SVG 对不代表 PNG 对；产物链每一环（SVG/PNG/打印页）单独验。
4. **生成视觉产物前先问清样式**（白边大小、是否加文字标注），别凭感觉批量生成。
5. 普通二维码（`make_qr.py`，扫码开网址）和 ArUco 码（纯几何图案，识别端扫 ID 反查位置）**是两码事**。

### 8.6 `.bat` 必须存成 GBK
本机 cmd 代码页 936。用 UTF-8 写含中文的 bat，cmd 会把字节当命令执行（一堆 `'xx' is not recognized`），
`chcp 65001` 也救不了。**结论：bat 里只写 ASCII 输出，文件存 GBK。**

### 8.7 本机 `pip` 和 `python` 是两个解释器
装包必须 `python -m pip`。

### 8.8 Chrome 无头截图必须用绝对 Windows 路径
相对路径报"拒绝访问 (0x5)"。要 WebGL 必须加
`--enable-unsafe-swiftshader --use-angle=swiftshader`。本地 http 页跳 https 时
`--virtual-time-budget` 不退出会卡住，分段验证。

### 8.9 本机没有全局 `node`
`where node` 为空。DSH 自带 node 在
`C:\Users\35391\.dsh\dsh-runtimes\dsh-next-primary-runtime\dependencies\node\bin\node.exe`，
跑 bat 时把该目录临时加进 PATH。

### 8.10 缓存错配会把页面搞崩
曾出现"教室全都搜不到"，根因是缓存里旧 js 配新数据。修法三层：改文件名带版本 / 数据与脚本同源 /
页面加"数据版本"打印。

### 8.11 `export_map_data.py` 的 `KeyError`
`nodes[].id` 是全写（`"B2-3/n1"`），`edges[]` 是同层简写（`"n1"`），脚本直接 `nodes[a]` 就炸。
已加 `node_of()` 按楼层前缀补全。**浏览器侧一直是对的**（`js/router.js:34-36` 早就做了同样补全）。

### 8.12 扫描件墙线是深栗色，不是亮红
实测阈值：`r<175 & r-g>12 & r-g+b<430`。用 `r>80` 的亮红阈值会整片漏检。
