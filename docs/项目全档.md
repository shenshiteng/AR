# 第一部分 · 项目是什么

## 1. 原始目标

### 1.1 最初那句话

> **在走廊/门口贴二维码 → 扫码 → 页面告诉你"你在这里" → 选要去的实验室 → 画出路线 + 分步文字指引（支持多栋楼、跨楼层）。**

约束同时定死：**不用装 App、不用后端**。

### 1.2 用户给的项目背景（决定了所有技术选型）

日志 2026-10-20 记着用户当时交代的实际情况：

| 条件 | 对设计的影响 |
|---|---|
| **多栋楼** | 数据结构从一开始就要有 `buildings[]` + `links[]`（跨楼 `outdoor`） |
| **规模较大** | 必须有批量生成二维码的工具，不能一个个手画 |
| **已有平面图图片** | 坐标系直接用图片像素坐标；图片留空时才退化为示意图 |
| **只做查询端** | 不做管理后台、不做录入界面（后来的 `marker.html`/`import.html` 只是本地工具） |

这四条至今没变，是判断"某个新需求是否在项目范围内"的基准。

### 1.3 两条并行的目标线

| 线 | 目标 | 代表产物 | 定位方式 |
|---|---|---|---|
| **A. 网页扫码导航** | 扫码即定位、看整张地图和完整路线 | `index.html` → `fp-ar.html` | **二维码**（带 `?loc=` 参数） |
| **B. AR 极简导航** | 对准标记码扫一下 → 大箭头 + 一句话指引 | `ar.html` → `fp-ar.html` | **ArUco 码**（纯几何，靠 ID 反查） |

**两条线在 2026-11-11 合流**：扫 QR 与扫 ArUco 最终都落到同一个 `doLocate()`，朝向都算 `normal+180`，
所以决定**去掉 ArUco、只贴 QR**（详见第 7 章第 1 条）。

### 1.4 当前边界

**在范围内**：第二实验楼 **2/3/5 层已建**导航数据（104 间实验室、12 个定位点、7 条跨层链接）；
网页扫码导航、AR 箭头、三维沙盘、自动验收工具链。

**已有素材但尚未建模**：**1 层与 4 层** —— `_boards/f1.jpg`、`_boards/f1_all.png`（一楼）、
`_boards/f4.jpg`（四楼）是真实疏散板照片，随时可开工。

> ⚠️ **口径（2026-11-11 19:05 更正）**：早期文档反复写「没有 1 层和 4 层」，这是**错**的。
> 准确说法是**「1 层与 4 层尚未建模」**。`labs.js` 里查无 `B2-1`/`B2-4` 楼层对象，
> 只说明数据没建，不代表这两层不存在。

**明确不在范围内**（用户没要或已排除）：

- 管理后台（可视化增删实验室）—— 未开工
- 蓝牙信标 / 米级室内定位 —— 未开工
- 原生 App（论证后不推荐：低频行为，没人会为一个找路功能装 App）
- 微信小程序（论证为"目标形态"但未开工；卡在主体注册 + ICP 备案）

```bat
双击 start-server.bat          :: 起 http://localhost:8000
```

| 想干什么 | 打开 |
|---|---|
| 手机扫码后的导航页（**主入口**） | `http://localhost:8000/fp-ar.html` |
| 带定位参数试扫码效果 | `http://localhost:8000/fp-ar.html?loc=P-B2-01` |
| 总览地图 + 搜索 + 整条路线 | `http://localhost:8000/index.html?map=1` |
| **三维沙盘**（2/3/5 层可切换） | `http://localhost:8000/nav3d/index.html` |
| 三维沙盘直达某层 | `nav3d/index.html?floor=B2-2` / `B2-3` / `B2-5` |
| 三维单间排查 | `nav3d/index.html?probe=333` |

> `index.html` 不带参数会自动跳 `fp-ar.html`，这是设计如此，不是 bug。
> 电脑上 `file://` 也能开（数据走 `<script src>`），但**手机扫码必须 `http://`**，**手机摄像头必须 `https://`**。

**改完任何东西，跑 `tools\verify-all.bat`**（六步全绿才算没搞坏）。

## 6. 关键算法（改之前必须懂）

### 6.1 寻路（`js/router.js`）

- Dijkstra，边权 = 像素距离 × `metersPerPixel`；第三项显式米数优先。
- 同层 `edges` 可简写 `"n1"`，程序自动补楼层前缀（`router.js:34-36`）。
- 跨层走 `links`，`type:"stair"` 自动判"上到/下到"（比 `floors` 顺序），`outdoor` 拼楼栋名。
- 时间 = 总距离 ÷ 60 米/分钟（室内步速）。
- **"兜底换面"是寻路的万恶之源**：宁可报"不通"，也不许偷偷换一条不该存在的路。

### 6.2 AR 朝向（`fp-ar.html` + `js/ar-bridge.js` + `js/ar.js`）

一句话：**绝对朝向来自墙上的贴纸，罗盘只负责"你转了多少度"。**

1. 扫码那一刻人必然面朝贴纸 → 绝对朝向 = `normal + 180°`（来自图纸，不受现场磁场影响）。
2. 之后转身，罗盘只取**转角增量**，加到绝对朝向上。
3. 目标方向 = 当前位置的路线走向；两者相减 → 直行 / 稍向左(右) / 左转(右) / 掉头。
4. **不直接用罗盘绝对方位**：室内钢结构/配电箱/管道把磁场扭曲，实测这栋楼偏约 80°；
   但"转了 90°"这个增量是准的（偏差恒定，做差抵消）。

**罗盘处理**：单帧跳变 > 45°/120ms 的读数直接丢（防乱甩）；连续读数低通平滑（防手持抖动）；
**只用增量不用绝对值**。曾因"快速转身被过滤器永久丢弃"导致该拐不拐，已修（加连续 5 帧一致放行）。

### 6.3 计步（实时步行跟踪）

- 罗盘（DeviceOrientation，60Hz）→ 箭头跟转；加速度计（DeviceMotion）→ 迈步峰值计步。
- 位置用"沿路线的已走米数"表示：每步 +0.72 m → 重算在第几段走廊 / 下一个拐弯还有多少米。
- 进入拐点前 6 米箭头开始平滑偏；6~3.5 米显示"前方左转 · 还有 5 米"；3.5 米内变"左转 52°"；
  路口显示"就是这儿，左转"；距拐点 ≤5 米振动。
- 步长误差累积（走 70 米可能差 5~8 米），界面上有 `−5 米 / +5 米` 手动修正；走到下一个码再扫一次最准。
- 罗盘可关：退回"扫码瞬间锁定朝向"静态模式。方向整体反了 → 点「⇄ 反了」翻 180°。

> **方向算法的两次返工（别再走回头路）**：
> ❌ aim 指向"拐后那一段的末端" → 支廊只有 4.4 米，算出 129° 而非 90°，箭头歪 20~30°。
> ❌ look-ahead 取 pos+8 米 → 方向仍是斜的，且提前 8 米就开始偏（北走廊段长才 5.4 米）。
> ✅ **用"段的方向"而不是瞄点**：`aimAngle(pos)` 取当前段的 `ang`，到拐点 ≤ `TURN_LEAD` 时提前切到下一段。

### 6.4 墙清理（`tools/grid_to_js.py` 内置，用户拍板最终版）

1. **闭运算合并平行细线**（`close-cells=1`，合并间隔 ≤8px）—— 消灭第一人称里的"平行栅栏"。
2. **只删房间矩形深处的墙**（`interior-margin-px=8`）。
3. **路网保路**：`nodes+edges` 连了边的走廊，边线两侧 `corridor-half-px=12px` 内的墙格一律挖掉 ——
   "数据说能走就保证不挡"，节点落墙问题也随之解决。
4. 被删墙在俯视总览用黄色标出供核对。
5. **判定墙的准绳**：真实墙 = 房间框边线 + 楼外轮廓；房间内部与走廊中间的细条多是照片噪声。

### 6.5 楼梯（双跑折返）五条硬规则（2026-10-30 定，改动前先读）

1. **换层只认"上一层地面"**：`checkStairTransition` 阈值 `|z| ≥ 层高 − 0.02`。
   半层高(1.5m) 是**中间平台**，只转弯、绝不换层（曾用 0.499×层高 → 一上平台就变三层）。
2. **平台转弯的目标角必须每帧按当前位置重算**，锁死一次会"已转到位但永不满足放行"的原地死锁。
3. **坡度参数化按"可走范围"归一**，不是房间矩形：`pad=min(20, L*0.25)`（墙厚+玩家半径 12px）、
   `buf=min(10, span*0.3)`，`t` 在 `[pad+buf, L-pad]` 映射（0=进门平地末端，1=远端墙）。
   按矩形算，60~70px 的小楼梯间永远走不到平台。
4. **一份几何只留一个出处**：`axis/dir/pad/buf/plat` 全放 `world.stairs`（fp-core 生成），
   高度场 / 3D 台阶 / 页面转弯判定全读它。谁再"猜门在哪一侧"必然漂移。
5. **门侧用跨层边上的楼梯口节点判定**（`buildWorld` 传 `stairDoors`）。用"离房间中心最近的路点"会判错：
   东南/西南楼梯间的门在正南，斜上方走廊节点却更近。窄楼梯间跑道中心夹 `LANE_MARGIN=24`。

### 6.6 三维沙盘的路网模型（`nav3d/tools/check_grid.py`）

- **楼板只存在于 `corridors` + `spurs` 上，其余全挡**（不许"默认全图可走"，大图上必然穿墙）。
- 房间靠"门点外 44px 落在走廊里"判通 → **走廊必须盖住每个门点**
  （例：北排房间门 S → 门点 y442+44=486，走廊 y442-495 必须覆盖 486）。
- 连通块数必须 = 1，否则该层一定有点不动的房间。
- 栅格模型固定顺序：**① 全图先挡死 → ② 挖开 corridors/spurs → ③ 把 wallRuns 挡回去 →
  ④ 中庭/楼梯/楼体缺口/solids 保持挡死**。

### 6.7 三维页面参数（别乱改）

- `pxPerMeter=26`；**墙高 1.8m**（试过 3.4 / 2.2 都不行，走廊只有 2m 宽，墙再高绿色路线被完全遮住）。
- **俯角 42°（`polar = 0.838`）**：标准等轴测 35.26° 在窄走廊下同样被遮，42° 是能看清路线的最小值。
- 正交相机 + 相机在 (1,1,1) 方向；路线管道半径 0.42m、抬高 0.55m；门洞宽 2.4m。
- 自检入口 `?noauto=1&selftest=1`，单间排查 `?probe=<房间ID>`，取景 `focus(id, margin)`。
- 套间（334/335 via 333、234/235 via 233）必须同时满足：① 宿主可达 ② 门开在与宿主共用的那道墙上
  且落在宿主跨度内 ③ 自己那道门不许直通公共走廊。

### 6.8 房间矩形提取方法（从疏散图照片量房间，已验证有效）

**直接连通域 / Hough 都不行**（照片有光照渐变、红线不闭合、相邻房间会被合并）。有效方法：

1. 颜色掩膜用 **Lab 的 a 通道 > 138**（比 HSV 稳）；扫描件墙线是深栗色，阈值
   `r<175 & r-g>12 & r-g+b<430`（**别用 `r>80` 的亮红阈值，会整片漏检**）。
2. **按行带/列带分区投影**：先全局行投影找关键横墙，再对每个行带做列投影
   （阈值取带高的 **0.7**）找竖隔墙；反向做行投影得横隔墙。
   文字笔画只有 50~60px，区分度极高。
3. 结果必须**叠加回原图画核对图**再定稿（`draw_plan.py`）。
4. **看图判断像素坐标前，先确认显示的是原尺寸还是缩放图** —— 曾因 1088 宽的显示图误导，
   把楼梯判成 x1275~1360（实际 1421~1553）。可靠做法：原图上用 `cv2.line` 画已知坐标参考线再截图核对。

## 8. 踩坑清单（必读，勿再犯）

### 8.1 全局命名冲突（2026-10-26，最贵的坑）

js-aruco2 的全局对象叫 **`AR`**。页面脚本里绝不能再定义 `var AR`（曾把桥接模块命名 AR，
遮蔽识别库 → 扫码报"识别库没加载"）。桥接模块现名 `Nav`（页面内）/ `window.__AR__`（全局）。

**新起变量名前先 grep 全局名单**：`THREE` / `AR` / `LAB_DATA` / `FLOOR_*` / `FPWorld` / `FPView` /
`FPInput` / `FPValidate` / `LabRouter` / `ARBridge` / `ArucoMark` / `FloorDetect` / `FloorImport` /
`__FP__` / `__AR__` / `__arDebug`。
（注意 `AR` 是识别库的、`__AR__` 是自有桥的，**差一个下划线，极易混**。）

> 排查时别只在外层 `typeof AR` 看，那永远是识别库的；要进页面 IIFE 作用域看。

### 8.2 功能修复必须端到端验证真实触发路径（2026-10-26 立的规矩）

无头浏览器可用「`canvas.captureStream()` 伪造摄像头 + 画布画 ArUco 码 + `addInitScript` 覆盖
`getUserMedia`」完整测扫码定位链路。**无头浏览器没摄像头就不测扫码 → "识别库没加载"这个 bug 活了 6 天。**

### 8.3 测试失败先怀疑测试脚本本身

已发生过的：尺寸裁切（画布 280px 装不下 7×40=320px 的码）、sed 替换漏 `const`、
`--virtual-time-budget` 卡住、落点偏置导致误报"卡住"、起点还写着已删除的节点。

### 8.4 手机端摄像头/罗盘必须 https

`isSecureContext` 为假时要在**页面横幅明说原因**，绝不静默 catch。

### 8.5 ArUco 码生成

1. **画图逻辑写反 → PNG 全纯黑块**：先画 7×7 大黑框后，应画 `'1'` 白格（fill=255）挖出图案；
   写反成画 `'0'` 黑格（本来就黑=没画），结果码区一整块黑、12 张全一样。
   生成后自查"图里是否真有图案"（黑像素占比是否随码不同而变）。
2. **别手写 BMP 冒充 PNG**：用 PIL 生成真 PNG。
3. **自检要验"最终产物"本身**：SVG 对不代表 PNG 对；产物链每一环（SVG/PNG/打印页）单独验。
4. 普通二维码（扫码开网址）和 ArUco 码（纯几何，识别端扫 ID 反查位置）**是两码事**。
5. **ArUco 能删到多简**（双解码器交叉验证）：白边能压到 0.05 格（5px）仍可识别，**0 白边两个解码器全失败**；
   **黑边框绝不能删**（它比内部数据更脆弱）；静区不必纯白（灰度 230/200/160 都能识别）。
   把网格线/彩色描边/0-1 数字画在码上 → 扫不出来，说明文字必须在码区外。

### 8.6 `.bat` 必须存成 GBK

本机 cmd 代码页 936。用 UTF-8 写含中文的 bat，cmd 会把字节当命令执行（一堆 `'xx' is not recognized`），
`chcp 65001` 也救不了。**结论：bat 里只写 ASCII 输出，文件存 GBK。**（2026-11-11 二次实证）

### 8.7 本机 `pip` 和 `python` 是两个解释器

装包必须 `python -m pip`。`pip` 指向 `AppData\Local\Programs\Python\Python313\Scripts\pip.exe`，
而 `python` 是 DSH 自带的 3.13。装错解释器会 `import cv2` 报 ModuleNotFoundError。

### 8.8 Chrome 无头截图必须用绝对 Windows 路径

相对路径报"拒绝访问 (0x5)"。要 WebGL 必须加
`--enable-unsafe-swiftshader --use-angle=swiftshader`。要读画布像素必须 `preserveDrawingBuffer:true`。
本地 http 页跳 https 时 `--virtual-time-budget` 不退出会卡住，分段验证。

### 8.9 本机没有全局 `node`

`where node` 为空。DSH 自带 node 在
`C:\Users\35391\.dsh\dsh-runtimes\dsh-next-primary-runtime\dependencies\node\bin\node.exe`，
跑 bat 时把该目录临时加进 PATH。

### 8.10 缓存错配会把页面搞崩

曾出现"教室全都搜不到"，根因是缓存里旧 js 配新数据。修法：改文件名带版本（`?v=7`）/
数据与脚本同源 / 页面加"数据版本"打印。

### 8.11 `export_map_data.py` 的 `KeyError`

`nodes[].id` 是全写（`"B2-3/n1"`），`edges[]` 是同层简写（`"n1"`），脚本直接 `nodes[a]` 就炸。
已加 `node_of()` 按楼层前缀补全。**浏览器侧一直是对的**（`js/router.js:34-36` 早就做了同样补全）。

### 8.12 扫描件墙线是深栗色，不是亮红

实测阈值：`r<175 & r-g>12 & r-g+b<430`。用 `r>80` 的亮红阈值会整片漏检。

### 8.13 "节点落墙"查不出"节点落在房间里"

节点落在某房间**内部**时，`isWallPx` 是 false（那里不是墙），检查全过 —— 但那个房间的门等于没了。
只有"边穿墙"检查才暴露它（曾有一整条中庭东缘走廊被房间盖住）。**必须两种检查都跑。**

### 8.14 两排房间"贴死"比"留缝"更常见地出错

从照片量出 944/1029 就把 329 顶边也设成 1029，默认了"相邻房间共用一道墙"。
实际走廊两侧房间是**各自独立两道墙 + 中间走道**。
**凡是"一排房间下面紧接另一排"，先怀疑中间有没有走廊，用逐行红量确认，别用阈值峰值。**

### 8.15 改了门/墙方向，一定要回头看 `perimeter`

`gen_perimeter.py` 用房间/走廊/支廊并集算外轮廓，凡没被覆盖的空隙它都当"楼外"。
曾把 315 西墙、西北楼梯东墙、东南楼梯南墙、走廊边全建成实墙 → 门改了也被糊死。
这类"假外墙"不挡寻路（栅格只认 corridor/spur），**只挡眼睛，会让人误以为改动无效**。

### 8.16 说明图的绿色虚线会被当成"施工待办"

出改动说明图时，"已拆墙"这类非常规操作图例要写得极明确（或干脆不画）。

### 8.17 交付给用户"打开就能看"的页面，依赖必须内联成单文件

相对路径只要跨出当前目录（`../`），在预览面板、分享链接、单独拷贝时一定会断。
nav3d 因此白屏过一整轮。

### 8.18 three.js 的 ShapeGeometry 不能直接 `rotateX`

不居中的 ShapeGeometry 会绕原点转，必须 `geo.center()` 或用 mesh 级 rotation。
PlaneGeometry（居中）无此问题。排查"楼板消失/透视"先用 bounding box + 顶点 world 坐标。

### 8.19 正交相机手写视野常数一定翻车

`resize()` 第一行 `if (!w || !h) return;`，在预览面板/iframe 里初始化时 `clientWidth/Height` 可能还是 0
→ 直接 return，再没有任何地方重算 → 投影矩阵永远停在 `OrthographicCamera(-1,1,1,-1)`，
**视野只有 2×2 米**，67m 的楼完全在框外。**必须按包围盒算（Box3 取 8 角点）。**

### 8.20 多会话并行时，任何"权威清单"都有保鲜期

核对数字前先看 `LastWriteTime`，最近 25 分钟改过的文件要重新算。
盘点目录必须 `Get-ChildItem` 全量列出，别凭印象（`_boards/` 曾漏掉近 40 分钟、三轮盘点都没提到）。
