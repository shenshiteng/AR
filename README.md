# 实验室定位（扫码找实验室）

一个不用装 App、不用后端的网页应用：**在走廊/门口贴二维码 → 扫码 → 页面告诉你"你在这里" → 选要去的实验室 → 画出路线 + 分步文字指引（支持多栋楼、跨楼层）。**

现在项目里装的是**第二实验楼 2 / 3 / 5 层**的真实数据（1 栋楼 / 3 层 / 104 间实验室 / 12 个定位点，没有 1 层和 4 层），平面图就是那几张疏散图。以后加别的楼、别的层，照第 4 节的流程复制一份就行。

> **第一次接手这个项目？先看 [`docs/项目全档.md`](docs/项目全档.md)** —— 唯一权威文档：目录地图、数据表、算法、硬规则、踩坑、验收命令、需求时间线与成果清单，一份读完就能接手。
> 想快速上手而不想看全档，看 [`docs/接盘说明.md`](docs/接盘说明.md)（精简版入口）。
> 本 README 讲的是"功能怎么用"，接盘说明讲的是"代码怎么接着改"。

## 1. 先跑起来（30 秒）

**方式 A（推荐）**：双击 `start-server.bat`，浏览器会自动打开 `http://localhost:8000`。

**方式 B**：在 VS Code 里打开这个文件夹 → 终端里执行：

```bash
python -m http.server 8000
```

然后浏览器打开 `http://localhost:8000`。

> 为什么要起服务而不是直接双击 `index.html`？因为手机扫码必须通过 `http://` 访问。电脑上看效果两种都行。

**试一下完整流程**：打开 `http://localhost:8000/?loc=P-A1-01`，这相当于"你在 A 栋 1 层大门内侧扫了码"。点任意实验室，就会看到路线、换层提示和分步说明。

## 2. 手机上真机测试

1. 手机连**同一个 WiFi**（和电脑同一个路由器）。
2. 双击 `start-server.bat` 启动服务（窗口别关）。
3. 双击运行 `tools/make_qr.py` 生成二维码，终端会打印出手机能用的地址，例如：

```
✓ P-A1-01   A栋 1层 · 大门内侧   http://192.168.3.41:8000/?loc=P-A1-01
```

4. 打开 `qr/print.html`，`Ctrl+P` 打印，贴在对应位置；或者直接用手机扫屏幕上 `qr/` 里的 SVG。
5. 手机扫码 → 直接进入定位页。

> 换网络（比如从家里到实验室）IP 会变，**重新跑一次 `make_qr.py`** 即可。等以后部署到公网，用 `python tools/make_qr.py --base https://你的域名` 生成的二维码就永久有效。

## 4. 三个常见操作

### ① 换成我的平面图

1. 把图片放进 `assets/floors/`，命名建议 `楼栋-楼层.png`，例如 `A-2.png`。
2. 用 `tools/marker.html` 打开这张图，标好房间、节点、连线（见下）。
3. 在 `data/labs.js` 里把对应楼层的 `"image"` 改成 `"assets/floors/A-2.png"`，`width/height` 改成图片的像素尺寸。

> 没有图也能用：`image` 留空，页面会自动画一张"示意平面图"（就是现在示例数据看到的样子）。

### ② 用标点工具标楼层（重点）

电脑上直接双击 `tools/marker.html`（不需要服务），然后：

1. 点「选择平面图图片」，**选完会自动识别**——青色虚线就是识别结果：房间框、走廊路点、连线一次出来。
2. 看着不对就调两个滑块再点「重新识别」：
   - 房间连成一大片 → 调大「房间封口」
   - 房间整块消失 → 调小「房间封口」
   - 漏掉浅色墙 → 调大「墙线阈值」
3. 满意后点「应用到标注」，再把房间号改成真实门牌号（`R1`、`R2`… 是自动编号）。
4. 识别漏掉的东西（楼梯间、小隔间）用工具栏手动补：拖框画房间、点走廊加节点、点两个节点连线。
5. 点「复制」，把 JSON 粘进 `data/labs.js` 的 `floors` 数组。
6. 每层重复一次；楼梯/电梯的连接写在 `links` 里（见 `docs/数据说明.md`）。

**识别的原理和边界**（知道这些就不会白折腾）：

- 原理：把深的像素当墙 → 把「自由空间」按门口宽度收缩一次，门口被掐断，剩下的每一坨就是一个房间 → 再在走廊里撒点、两点之间直线不穿墙就连一条边。
- 它**只认几何形状，不认字**：房间号、面积标注这些文字它看不懂，所以房间号要你自己改。
- 图上**没画门**的房间会和走廊断开，工具会提示「有 N 个路点没连上主路网」——补一个门洞，或手动连一条线。
- 拍照/歪斜/很花的图效果差，**最好是原始 CAD 导出的正面图**（PNG/JPG 都行，3000px 宽的图识别约 0.2 秒）。

**只要节点连成一条通的路，寻路就一定能算出来**；漏连一段，就会出现"暂不可达"。

### ③ 加一间实验室 / 加一个二维码

- 加实验室：在 `labs` 数组里加一条，`floor` 写楼层 ID，`room` 写房间 ID，`door` 写门口最近的**节点 ID**。
- 加二维码：在 `locations` 数组里加一条（`floor` + `node` + `place`），再跑一次 `make_qr.py`。

## 5. 数据是怎么变成"人话"的

- 每个节点有个 `note`（如"楼梯电梯厅"），每一步的文字就是 `起点 → 终点 + 距离`。
- 距离 = 图上两点像素距离 × `metersPerPixel`（示例里 1000px ≈ 50 米）。
- 跨层用 `links`，类型写 `stair`，程序会自动判断"上到/下到"；跨楼写 `outdoor`。
- 时间 = 总距离 ÷ 60 米/分钟（室内步速，想更保守可以在 `router.js` 里调）。

## 6. 遇到问题

| 现象 | 原因 / 解决 |
|---|---|
| 手机扫码打不开 | 手机和电脑不在同一 WiFi；或电脑防火墙拦了 8000 端口；或 IP 变了要重新生成二维码 |
| 打开页面一片空白 | 用浏览器 F12 看 Console。多数是 `data/labs.js` 改坏了（JSON 格式错误，比如多了逗号） |
| 某个实验室显示"暂不可达" | 该实验室 `door` 指的节点没连到主走廊，或跨层 `links` 没写 |
| 平面图不显示 | `image` 路径不对，或图片没放进 `assets/floors/`。此时会自动退回示意图 |
| 路线绕远 | 节点太少/连错边。补几个中间节点，或把穿过墙的那条边删掉 |
| 三维沙盘转不动 / 一片背景色 | three.js 没加载到。成品 `nav3d/index.html` 是内联的，正常不会；若是 `_dev.html`，检查 `js/vendor/three.min.js` |
| 三维沙盘某层房间点不动 | 该层路网断了。跑 `cd nav3d && python tools/check_grid.py <层>`，连通块必须是 1 |

**卡住了就跑一键验收**：`tools\verify-all.bat`。它会告诉你坏在哪一层、哪一步。

## 8. AR 扫码导航（按需求文档做的 MVP）

`ar.html` 就是那份《校园教室 AR 极简导航系统》的落地版本：
**对墙上的 ArUco 码扫一下 → 知道你在哪、面朝哪 → 输入教室 → 屏幕给大箭头 + 一句话指引。**

### 8.1 三步跑通

1. **打印定位码**：打开 `tools/aruco-print.html`，`Ctrl+P`，A4 一页 4 张，沿边剪下。
2. **贴**：贴在楼梯口 / 电梯口 / 走廊拐点。**卡片上「↑ 上边朝上」必须真的朝上**——这决定"左转/右转"算得对不对。
3. **用**：手机打开 `ar.html` → 允许相机 → 对着码扫一下 → 输入教室号 → 跟着箭头走。

### 8.2 手机上必须用 https（重要）

浏览器只在**安全上下文**里允许调用摄像头，`http://192.168.x.x` 在手机上会被直接拒绝：

- 电脑本机调试：`http://localhost:8000/ar.html` 可以（用电脑摄像头）
- 手机真机：**必须 `https://` 的地址**。把项目发布到公网即可。

### 8.3 方向是怎么算出来的

一句话：**绝对朝向来自墙上的贴纸，罗盘只负责"你转了多少度"。**

1. 每个定位点在 `data/labs.js` 里有 `marker`（ArUco 编号）和 `normal`（贴纸正面朝哪个方向，图上方为北：0=东，90=南，180=西，270=北）。
2. 人扫码时必然是**站在码前面朝墙**，所以扫码那一刻的绝对朝向 = `normal + 180°`。**这个值来自图纸，不受现场磁场影响，非常可靠。**
3. 之后你转身、走动，罗盘测出**转角变化量**，把它加到那个绝对朝向上。
4. 目标方向 = 你现在所在位置的路线走向；两者相减 → 直行 / 稍向左（右）/ 左转（右转）/ 掉头。

> **为什么不直接用罗盘的绝对方位？**
> 室内有钢结构、配电箱、管道，磁场被严重扭曲，罗盘指向常常偏 30~90°（实测在这个楼里偏了约 80°）。
> 但**"转了 90°"这个变化量是准的**——因为偏差是恒定的，做差就抵消了。
> 所以这里拿贴纸定基准、拿罗盘量增量，两者的优点都用上了。

**如果方向整体反了**（箭头一直指背后）：点导航界面上的 **「⇄ 反了」**，会立刻翻转 180°。多半是贴纸朝向填反了，或者扫码时你没有正对着码。

### 8.4 实时步行跟踪（像高德 AR 步导那样边走边更新）

导航页不是"扫完码定死"，而是**一边走一边更新**。室内没有 GPS，靠手机自带的两个传感器：

| 传感器 | 拿到什么 | 用在哪 |
|---|---|---|
| 罗盘（DeviceOrientation） | 手机转了多少度，60Hz | 你转身，箭头立刻跟着转 |
| 加速度计（DeviceMotion） | 迈步的加速度峰值 → 计步 | 走了几步 × 0.72 米 = 走了多远 |

位置用「沿路线的里程」表示（已走米数）。每计一步，里程 +0.72 米，然后立刻重算：

- 我现在在第几段走廊上
- 下一个拐弯还有多少米
- **进入拐点前 6 米，箭头就开始平滑偏过去**（不是到路口才突然拐）
- 距拐点 6~3.5 米：大字显示「前方左转 · 还有 5 米」，提醒你要拐但还没到，别提前拐
- 距拐点 3.5 米内：大字变「左转 52°」，配「再走 2 米就左转」
- 走到路口：「就是这儿，左转」
- 剩余米数实时递减，进度条实时增长
- 距拐弯点 ≤5 米时振动一下（不用一直盯屏幕）
- 走到终点 → 大字变「已到达」+ 振动

界面上能看到：`已走 14 米 / 还剩 60 米 / 计步 20 步`。

**计步有累积误差**（步长因人而异，走 70 米可能差 5~8 米），所以进度条旁边有 `−5 米 / +5 米` 两个按钮手动修正；另外**走到下一个定位码再扫一次**就是最准的重定位。

**罗盘关掉也还能用**：此时退回"扫码瞬间锁定朝向"的静态模式，只是不会跟着你转身。按钮在右上角，可以随时开关。

**室内磁场干扰的处理**：单帧跳变超过 45°/120ms 的读数直接丢掉（防乱甩），连续读数做低通平滑（防手持抖动），并且**只用增量不用绝对值**（防磁场导致的方向偏差）。

### 8.5 关于「读取码的偏转角度」

文档里写"读取码的偏转角度算出手机朝向"，严格说：单个平面码只能算出**手机有没有歪**（滚转角），算不出你面朝东南西北；要算真朝向得用相机内参做位姿解算（POSIT），小码上噪声很大。所以这里用的是更稳的组合：**扫码位置 + 墙面法线 + 罗盘**。码的倾斜角仍然读了，用来提示"手机拿正一点"。

### 8.6 两种入口怎么配合

| 入口 | 贴在 | 体验 |
|---|---|---|
| ArUco（`ar.html`） | 走廊、楼梯口、电梯口 | 打开 App 内扫码，方向校准最准 |
| 二维码（`index.html`） | 大门、房间门口 | 扫码直接打开网页并定位，能看整张地图和完整路线 |

两个入口共用同一份 `data/labs.js`，改一处两边同时生效。

## 9. 图片转数字地图（把平面图变成可导航数据）

原来「识别 → 改房间号 → 手工把每间房的门挂到走廊节点 → 粘 JSON」全靠人，
其中**挂门**最费神也最容易错（之前就整排挂错过，路线停在墙外）。现在这条链路自动化了。

### 9.1 两条路，看你要什么

| 场景 | 用哪个 | 产出 |
|---|---|---|
| 一张图快速变成**能跑的**数据 | `tools/import.html` | `floors[]` + `labs[]`，一次生成 |
| 识别不准、要手动改框和路网 | `tools/marker.html`（精修后点「生成 labs」） | 同样两份数据 |

**推荐流程**：先用 `import.html` 出一版草稿 → 拿草稿跑一遍看路线对不对 →
不对的地方用 `marker.html` 精修 → 精修完点「生成 labs」重新挂门。

### 9.2 数据是怎么流过去的

```
平面图图片
   │  floor-detect.js        analyze(img, {threshold, sealPx})
   ↓
{ rooms:[{x,y,w,h}], nodes:[{x,y}], edges:[[i,j]], stats }
   │  floor-import.js        build(res, {floorId, building, name, image, roomNumbers})
   ↓
{ floor:{id,building,name,image,width,height,nodes,edges,rooms},
  labs:[{id,name,floor,room,door,tags}],
  warnings:[...] }
   │  粘进 data/labs.js
   ↓
router.js / ar.js / app.js 直接可用（结构完全沿用现有的，一行代码都不用改）
```

### 9.3 两个模块对外接口

**`FloorDetect.analyze(img, opt)`** —— 纯图像处理，不联网、不用模型

| 参数 | 说明 |
|---|---|
| `opt.threshold` | 墙线灵敏度 80~200，越大越容易判成墙（默认 120） |
| `opt.sealPx` | 房间封口半径，房间连成一片就调大（默认按图短边 2.8% 算） |
| `opt.maxSide` | 识别前把图缩到多长边（默认 1600，大图更快） |

输出 `rooms`（房间外框）、`nodes`（走廊路点）、`edges`（可通行连线）、`stats`（含 `islands` 孤岛数）。

**`FloorImport.build(res, opt)`** —— 识别结果 → 可导航数据

| 参数 | 说明 |
|---|---|
| `opt.floorId` / `building` / `name` | 楼层标识，如 `B2-4` / `B2` / `4层` |
| `opt.image` / `width` / `height` | 平面图路径与像素尺寸 |
| `opt.roomNumbers` | 门牌号，逗号分隔，按「从上到下、从左到右」对应；留空用 `R1…` 占位 |
| `opt.maxDoorDist` | 门离房间超过多少像素就警告（默认图短边 16%） |

**自动挂门怎么做的**：每个房间找「离它最近、且不在任何房间框里」的路点——不在框里就意味着在走廊上。
如果房间框本身识别得偏大（合计面积超过整图 55%，实拍照片常见），就退化成「最近的点」并给出警告，
因为这时候靠"在不在框里"判断走廊已经不可靠了。

### 9.4 实测：链路是通的，瓶颈在图源

| 图 | 房间 | 路点/连线 | 孤岛 | 可导航 |
|---|---|---|---|---|
| 干净 CAD 风格图（1000×640） | 8/8 全中 | 86 / 186 | **0** | **8/8 全部可达** |
| 手机拍的疏散图（1791×1920） | 12（实际 36 间） | 87 / 88 | **72** | 1/8 可达 |

结论：**算法本身没问题，是实拍照片太糊**（纸面反光、有明暗渐变、红线又细）。
要效果好，请用 CAD 导出的图（dwg → 图片），或者把扫描件放正、提高对比度再识别。

孤岛数（`stats.islands`）是最重要的体检指标：**它不为 0，就说明有房间没连上路网**，
那些房间一定算不出路线——去 `marker.html` 里补一条连线即可。
